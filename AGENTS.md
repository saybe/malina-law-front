# AGENTS.md

Инструкция для ИИ-агентов и моделей, работающих с этим репозиторием.
Прочитай целиком до того, как что-либо менять.

Проект human-readable: [README.md](README.md) — там архитектура и команды.
Этот файл — про то, **как** работать здесь и где грабли.

---

## Что это

Статический сайт на React + Vite, публикуется через GitHub Pages.
Данные — правовые акты РФ с официального портала
`http://publication.pravo.gov.ru` (только HTTP, без TLS).

Страница **не ходит** на портал из браузера. Данные забирает GitHub Actions и
складывает в `public/data/acts.json`; страница читает этот файл с того же
origin. Так обойдены mixed content (Pages только HTTPS) и CORS.

## Структура

```
scripts/fetch.mjs        скачивание и нормализация актов — Node stdlib, 0 зависимостей
scripts/check.mjs        проверка данных и логики фильтров — Node stdlib, 0 зависимостей
public/data/acts.json    генерируется, коммитится в репозиторий
public/config.js         необязательный внешний jsonUrl
src/lib/acts.js          загрузка, кэш, фильтры, поиск, форматирование
src/App.jsx              состояние, группировка по датам
src/components/          ActCard, Toolbar, Freshness
src/styles.css           единственный файл стилей
.github/workflows/       расписание + деплой
```

## Команды

Нужен Node.js 20+.

```bash
npm install
npm run fetch   # скачать акты → public/data/acts.json
npm run check   # ~45 проверок данных и фильтров; ненулевой код = провал
npm run build   # сборка в dist/
```

**Правило: после изменения `scripts/fetch.mjs` обязательно запусти
`npm run fetch && npm run check`.** Без этого ты не знаешь, что разбор портала
не посыпался.

`fetch` ходит на живой портал и занимает 30–60 секунд. Не вызывай его в цикле и
не запускай параллельно несколько копий: портал отвечает `HTTP 500` на
параллельные запросы, поэтому внутри скрипта они идут строго последовательно.

## Жёсткие ограничения

1. **В `scripts/fetch.mjs` нельзя добавлять зависимости.** Только стандартная
   библиотека Node. Скрипт обязан запускаться на голом раннере GitHub, где
   `npm ci` для его зависимостей ещё не выполнен.
2. **Ветка — `master`**, не `main`. В workflow пушится `HEAD:master`.
3. **`dist/` не коммитится** (в `.gitignore`). Сборка — артефакт деплоя.
4. **Не ходи с браузера напрямую на портал.** Это ломает mixed content. Только
   `public/data/acts.json` или `jsonUrl` из `public/config.js`.
5. **Пароль или токен в код, в URL и в историю git не попадают.** Никогда.
6. **Коммиты не делаешь, пока тебя не попросили.** Правило общее, не
   специфичное для репозитория.
7. **Стили — только `src/styles.css`.** Нет CSS-модулей, препроцессоров и
   UI-кита. Новые зависимости в `package.json` не добавляй без явной просьбы.

## Ловушки, об которые уже спотыкались

### 1. `\b` и `\w` в JS не работают с кириллицей

`\b` и `\w` — это ASCII. Кириллические буквы «word-символами» не считаются, и
`/Протокол\b/` **не срабатывает никогда**: после «л» идёт пробел, а границы слов
между двумя не-ASCII символами нет. `\w+` аналогично не матчит русские слова.

```js
/Протокол\b/                 // ❌ не сработает
/^(?:Протокол|Соглашение)(?![А-Яа-яЁёA-Za-z0-9])/   // ✅
```

Таких мест в проекте уже было три, все исправлены — см. комментарий в начале
раздела «Разбор RSS» в `scripts/fetch.mjs`. **Не возвращай `\b` в русские
регулярки.**

### 2. `block=all` на портале — это `HTTP 500`

Общая лента получается **без параметра `block`**. Любое несуществующее значение
(`all`, `null`, `regional`) портал отвергает с `HTTP 500`. Именно так
`block=all` стоил получаса отладки.

### 3. `pageSize` больше 200 — `HTTP 400`

Максимум — 200 записей на раздел. Глубокая история недоступна в принципе.

### 4. Поле `description` — единственный надёжный источник даты

Дата публикации лежит в `description` как `Дата опубликования: 24.09.2025` —
со всеми буквами. В заголовке дата есть не всегда, а у международных документов
записана словами. В `pubDate` портал местами отдаёт мусор, поэтому он только
резервный вариант.

### 5. Заголовок акта приходит одной строкой с `\r\n` внутри

`<title>` содержит перевод строки между номером и названием. Схлопывай пробелы
через `.replace(/\s+/g, ' ')`, иначе в JSON попадут `\r\n` и вёрстка поедет.

### 6. ФЗ публикуются пачками

В проверенных данных 78 федеральных законов вышли одним днём, а между пачками
проходит несколько недель. «За последние 30 дней нет ФЗ» — это норма, а не баг.
Окно хранения поэтому 60 дней, а не 30. Не «чини» это, не урезая окно.

### 7. Разделы `council_1` и `council_2` на портале заморожены с сентября 2025

Актов Госдумы и Совета Федерации в ленте не будет. Скрипт это отмечает в
`staleSections`, сайт показывает предупреждение, `check.mjs` это проверяет. Не
пытайся «починить» — проблема на стороне источника.

### 8. Портал отдаёт `HTTP 500` на параллельные запросы

Отсюда последовательные запросы с паузой `GAP_MS` в `fetch.mjs`. Не переводи на
`Promise.all` ради скорости.

## Формат данных

`public/data/acts.json` — полная схема описана в README. Ключевое:

- `id` — номер опубликования, он же идентификатор и ссылка;
- `level: 'federal' | 'other'` — по этому флагу сайт решает, показывать ли акт в
  режиме по умолчанию;
- `name` **всегда непустая строка** (иначе туда кладётся заголовок целиком);
- `number` может быть `null` — акты без номера существуют.

Если меняешь схему — синхронно правь `scripts/fetch.mjs`, `scripts/check.mjs`,
`src/lib/acts.js` и README. Тест `check.mjs` специально проверяет целостность
этой схемы, так что расхождения поймаются.

## GitHub Actions

`.github/workflows/update.yml` — один job, порядок шагов важен:

```
fetch → check → build → коммит acts.json → push → deploy-pages
```

Коммит с данными **до** публикации: сбой на Pages не должен откатывать данные.
Шаг `fetch` с `continue-on-error` — при недоступности портала публикуется
предыдущая версия файла.

Если в логе `fetch` таймаут, а не `HTTP 500`, — раннер GitHub не достаёт до
`.gov.ru` из США. Проверить заранее нельзя. Лечится внешним эндпоинтом через
`jsonUrl` в `public/config.js` (см. README), **не** ослаблением TLS-проверок и
**не** переходом на публичные CORS-прокси — они не отвечают.

Расписание — раз в час: `cron: '17 * * * *'`. Внутри часа на портале всё равно
ничего не появляется, чаще нет смысла.

## Чего не делать

- Не «улучшать» разбор заголовков, не проверив результат на живом фиде. Правки
  регулярных выражений здесь ломают данные тихо: страница собирается, а текст
  становится мусором. Проверяй `npm run fetch && npm run check` и смотри лог.
- Не расширять окно истории без нужды: файл коммитится в git каждый час.
- Не добавлять тёмную тему «по умолчанию светлую наоборот» — она уже на
  `prefers-color-scheme`, в `src/styles.css` есть тёмные варианты всех цветов.
- Не убирать предупреждение об устаревших разделах: без него пользователь
  подумает, что данные пропали.
- Не хардкодить даты и ожидаемое количество актов в тестах. Тест проверяет
  свойства данных, а не снимок состояния на конкретный день.

## Проверка перед сдачей

```bash
npm run fetch && npm run check && npm run build
```

Ожидаемый итог: `Все проверки пройдены`, в `dist/` есть `index.html`,
`config.js`, `data/acts.json` и `assets/`, сборка без предупреждений.
