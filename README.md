# malina-law-front

Небольшой сайт, который показывает последние обновления законодательства
Российской Федерации с официального интернет-портала правовой информации.

**Сайт:** https://saybe.github.io/malina-law-front/

---

## Что это

Страница отдаёт акты, **опубликованные** на
[publication.pravo.gov.ru](http://publication.pravo.gov.ru/) — это официальное
опубликование, а не редакционные новости. Каждая карточка ведёт на документ на
портале.

Возможности:

- федеральный срез по умолчанию, переключатель «включая региональные акты»;
- фильтр по периоду: сегодня, 3 дня, неделя, месяц, всё;
- поиск по названию, номеру и дате (без учёта регистра и «ё/е»);
- избранное — хранится в `localStorage` браузера; переключатель «только
  избранное» и кликабельный счётчик `★ N` в панели фильтров. В избранном
  лежит **снимок акта**, а не его `id`: `id` существует только внутри текущего
  `acts.json`, и акт рано или поздно вытесняется лимитом 200 записей на раздел
  или окном в 60 дней. Старый формат (просто список `id`) читается и
  превращается в снимки на лету;
- индикатор свежести данных и кнопка «Обновить»;
- группировка по датам, тёмная тема по системной, адаптивная вёрстка.

## Как устроено

Ключевое техническое решение объясняет всю остальную архитектуру.

Портал `publication.pravo.gov.ru` отдаёт RSS и JSON с заголовком
`Access-Control-Allow-Origin: *`, но **только по HTTP** — на 443 TLS не
отвечает. GitHub Pages работает только по HTTPS, поэтому браузер заблокировал бы
прямой `fetch` как небезопасное содержимое (mixed content). Публичные
CORS-прокси для этого не помогают: все проверяемые на момент разработки
(allorigins, codetabs, corsproxy.io) не отвечали.

Поэтому данные готовит **GitHub Actions** и складывает в репозиторий, а страница
читает готовый JSON с того же origin. Никаких прокси и внешних зависимостей.

```
publication.pravo.gov.ru (HTTP, раз в час)
        │  scripts/fetch.mjs
        ▼
public/data/acts.json  ──►  коммит в master
        │
        ▼
   npm run build ──►  dist/ ──►  deploy-pages ──►  saybe.github.io
```

При каждом заходе на страницу всё равно уходит реальный запрос
(`?_=<время>` + `cache: 'no-store'`), поэтому обновления видны сразу после
публикации. Если сеть недоступна, страница показывает последнюю копию из
`localStorage` с пометкой «показана локальная копия».

## Разделы источника

Федеральные блоки портала запрашиваются все — они и образуют федеральный срез.
Региональные акты в них не попадают, для них берётся общая лента.

| block                 | Содержимое                                          |
| --------------------- | --------------------------------------------------- |
| `president`           | Федеральные законы, указы и распоряжения Президента |
| `government`          | Постановления и распоряжения Правительства          |
| `council_1`           | Совет Федерации                                     |
| `council_2`           | Государственная Дума                                |
| `federal_authorities` | Ведомственные приказы федеральных органов           |
| `court`               | Конституционный Суд РФ                              |
| `international`       | Международные договоры и протоколы                  |
| без параметра         | Общая лента — отсюда берутся региональные акты      |

> **Ограничение источника.** Разделы `council_1` и `council_2` на самом портале
> не обновляются с сентября 2025 года, поэтому актов Госдумы и Совета Федерации
> в ленте не будет. Скрипт это замечает и пишет предупреждение, сайт показывает
> его пользователю. Остальные разделы актуальны.

Ещё два ограничения, которые ниже не обойти:

- лимит источника — **200 записей на раздел**, поэтому глубина истории у разных
  разделов разная;
- федеральные законы публикуются **пачками**: в проверенных данных 78 ФЗ вышли
  одним днём, а между пачками проходит несколько недель. Поэтому окно хранения
  — 60 дней, а не 30.

## Формат `public/data/acts.json`

Файл кладётся в `public/`, Vite копирует его в `dist/` как есть. Пишется без
отступов — он коммитится в репозиторий каждый час, и размер важен.

```jsonc
{
  "updatedAt": "2026-09-26T16:33:10.994Z", // когда обновили
  "source": "publication.pravo.gov.ru",
  "sourceUrl": "http://publication.pravo.gov.ru/",
  "rangeDays": 60, // окно истории
  "cutoff": "2026-07-28", // дата отсечения
  "counts": { "total": 680, "federal": 567, "other": 113 },
  "sections": [
    // свежесть каждого раздела
    {
      "id": "president",
      "label": "Президент Российской Федерации",
      "count": 200,
      "latest": "2026-09-25",
    },
  ],
  "staleSections": [{ "id": "council_1", "label": "Совет Федерации", "latest": "2025-09-24" }],
  "items": [
    {
      "id": "0001202609250003", // номер опубликования, он же id
      "type": "Указ Президента Российской Федерации",
      "number": "680", // может быть null
      "date": "2026-09-25", // YYYY-MM-DD
      "name": "О первом заседании Государственной Думы…",
      "url": "http://publication.pravo.gov.ru/document/0001202609250003",
      "category": "Указ Президента", // для цвета бейджа
      "level": "federal", // federal | other
    },
  ],
}
```

`name` — всегда непустая строка: если заголовок не удалось разобрать, туда
попадает заголовок целиком.

## Команды

Нужен **Node.js 20+**.

```bash
npm install        # зависимости
npm run fetch      # скачать акты в public/data/acts.json
npm run check      # собрать типы и проверить данные и логику фильтров
npm run smoke      # проверить вёрстку компонентов
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm run format     # Prettier
npm run dev        # локальный сервер на :5173
npm run build      # сборка в dist/
npm run preview    # посмотреть собранное
```

`npm run check` сначала собирает исходники в `.check-out/` и только потом
запускает `scripts/check.mjs`. Проверка идёт обычным Node, а типы снимает `tsc`:
в Node 20 нет `--experimental-strip-types`. Проверяются только чистые модули —
те, где нет `fetch`, `localStorage` и `import.meta.env`, — поэтому логика,
тестируемая из Node, обязана лежать в них.

Скрипт прогоняет ~80 утверждений по настоящему файлу данных: целостность
структуры, наличие актов всех категорий, корректность фильтров по периодам,
поиска, группировки по датам и контракта избранного. Проверяет он в том числе,
что разделы помечены как устаревшие тогда и только тогда, когда на портале нет
свежих актов. Падает с ненулевым кодом — его вызывает GitHub Actions.

`npm run smoke` закрывает то, чего `check.mjs` не видит: он рендерит
компоненты в статическую разметку через `react-dom/server` и проверяет, что
звезда избранного действительно подсвечивается, тон метки соответствует
категории, а предупреждение об устаревших разделах читается по-человечески.
Браузер не нужен, SSR-сборку делает Vite.

## Структура кода

Слои как в FSD, но без церемонии: страница одна, роутинга нет, сущность одна.
`pages/` не заведён — `src/app/App.tsx` и есть корень композиции.

```
src/
  app/          App.tsx — только сборка экрана, хуки с состоянием
  widgets/      лента: список по дням, индикатор свежести, уведомления
  features/     избранное и фильтры — то, чем пользователь что-то делает
  entities/     акт: модель выбора и фильтрации, карточка
  shared/       даты, localStorage, загрузка данных
```

Правило зависимостей: `app` → `widgets` → `features` → `entities` → `shared`.
Обратные импорты запрещены, `index.js`-реэкспорты не плодим — у модуля один вход.

**Проверяемое из Node — только то, что лежит в `*/model/*`.** Эти модули обязаны
оставаться чистыми: ни `fetch`, ни `localStorage`, ни `import.meta.env`.
Нарушение не поймает линтер, но уронит `npm run check` или CI.

**Проверяемое в вёрстке — только то, что рендерится.** Хуки (`app/hooks`,
`features/*/model/use*`) — это склейка React-состояния с чистой логикой из
`model/`. Бизнес-логику в хуке не держим: её не видит ни `check`, ни `smoke`.

## Внешний источник (если Actions не достаёт до .gov.ru)

Раннеры GitHub физически находятся в США, и доступ к российскому порталу из них
не гарантирован. Если в логе воркфлоу шаг «Скачать акты» падает с таймаутом:

1. Поднимите HTTPS-эндпоинт, который отдаёт JSON в формате выше. Подойдёт
   Cloudflare Worker, Vercel Function или любой свой сервер.
2. Пропишите его в [`public/config.js`](public/config.js):
   ```js
   window.MALINA_CONFIG = { jsonUrl: 'https://ваш-эндпоинт/acts' }
   ```
3. Запустите воркфлоу вручную. Страница сначала попробует внешний адрес, а при
   неудаче откатится на файл из репозитория.

Пока `jsonUrl` пустая, страница читает `data/acts.json` из этого же репозитория.

## Деплой

`.github/workflows/update.yml` — раз в час (по `cron: '17 * * * *'`) и вручную
из вкладки Actions. Один job, шаги строго последовательные:

```
checkout → setup-node → npm ci → fetch → check → build
        → коммит acts.json + push → configure-pages → upload-artifact → deploy
```

Порядок важен: коммит с данными происходит **до** публикации, поэтому сбой на
этапе Pages не откатывает уже сохранённые данные.

- `fetch` идёт с `continue-on-error`: если портал недоступен, сайт публикуется с
  тем файлом, что уже лежит в репозитории, а в лог падает предупреждение.
- Коммит с данными делается, **только если файл изменился** — иначе шаг
  пропускается, чтобы не плодить пустые коммиты.
- В `master` попадает только исходник. `dist/` в `.gitignore`.

Настройка репозитория: **Settings → Pages → Build and deployment → Source =
GitHub Actions**. Ветка по умолчанию — `master`.

## Ограничения

- Данные обновляются раз в час, а не в реальном времени: официальный портал
  публикует акты пачками, внутри часа там всё равно ничего не появляется.
- Акты группируются по дате публикации, а не по дате вступления в силу.
  «Опубликован» ≠ «вступил в силу» — для правовой работы это важно, проверяйте
  по карточке на портале.
- Сайт ничего не интерпретирует и не резюмирует: это агрегатор, а не
  правовая помощь.
- Данные и сайт — только для личного использования.
